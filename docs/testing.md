# 测试体系：不打扰群友的四个层级

群聊机器人的测试难题：不能拿真实群友当小白鼠。本项目用四层体系解决，
核心思想是**用真实数据的"录音"测试，不用真人**。

## L0：纯逻辑单测（不碰 LLM、不碰群）

决策状态机、橡皮擦、水位线等都是纯逻辑，可以断言：
"@ 必回""周期外小概率苏醒""连续 N 次跳过下头""同一句话发两遍都要读到"。

## L1：日志回放（主力手段）⭐

鱼脑把所有群消息按天落盘（`brain/data/logs/<会话>/<日期>.jsonl`）。
回放器把真实日志按原顺序喂给鱼脑，看它"当时会说什么"：

```bash
# 服务器上把日志拷到本地（或直接在服务器上跑）
python tools/replay.py <日志文件.jsonl> \
  --brain http://127.0.0.1:6190/fish \
  --key <FISH_KEY> \
  --chat 回放组 \
  --limit 100
```

输出：每条触发消息 + 鱼的决策与回复 + 统计（mention/active/沉默/复读粗检）。

- 零打扰：群友根本不知道
- 真实数据：不是编的测试用例
- 版本对比：同一份日志，新旧鱼脑各跑一遍，直接看出差异

注意：回放会真实调用 LLM（一条命中一次），100 条约几分钱。
`--chat` 用一个假名字，避免污染真实群的记忆。

## L2：影子模式（真实群里只看不说话）

`hand/config.json` 设 `"dry_run": true`（或改文件里的默认值）：

- 鱼正常看群、正常调用鱼脑，但**回复不发送到微信**
- 本地窗口打印 `[影子] 鱼想说: ...`
- 挂一晚，第二天翻它的心理活动，满意再切 `false`

## L3：测试群

用自己的两个号建的小群，验证"发送链路"（引用、@、定时冒泡）。
只有 L0-L2 都过了才需要它。

## L4：真实群灰度

先只开 `@触发`（把 `FISH_ACTIVE_ENTER_PROB` 设为 0），稳定后逐步放开主动插话。

## 排查三板斧

| 症状 | 第一步查什么 |
|---|---|
| 鱼不回 | 鱼手日志有没有收到新消息（没有 → 窗口/视口问题，见 troubleshooting） |
| 收到了但沉默 | 消息含"大肥鱼"吗？不含就是判官决策，看 `/fish/logs` 的 mode 字段 |
| 回复内容怪 | 拿同一批消息用 replay.py 回放，本地复现后调人格卡 |

## 变更纪律（每次改代码必须遵守）

吃过亏立下的规矩：

1. **版本号递增**：`fish_hand.py` / `watchdog.py` / `brain/app.py` 顶部的
   `*_VERSION` 常量，任何行为修改必须 +0.1。启动横幅和健康接口会带上它——
   部署是否生效，看日志里的版本号一眼可判，不靠猜
2. **每个行为修改配一条日志**：新逻辑必须在日志里留下可观测的痕迹
   （如"慢环节: ChatWith 耗时 30s"），否则下次故障又是盲人摸象
3. **先跑测试**：`pytest tests/ -q`（22+ 例，0.3 秒），逻辑改动先写测试
4. **异常必须进日志文件**：禁止只 print 到 stderr
