# 改进指南：如何让鱼变聪明

本项目的回复逻辑是**有意保持简单的初级实现**（README「定位与局限」已声明）。
如果你愿意动手，这份文档把"不够聪明"拆成六个可独立改进的方向，
按**投入产出比**排序，每条都标明改哪里、参考什么。

> 改之前先读 [config.md](config.md) 的「决策逻辑速览」，并建议先收集至少一周
> 真实群聊日志（`/fish/logs` 接口或 `brain/data/logs/`），用真实问题驱动改进，
> 而不是凭想象优化。

---

## 1. 决策两阶段化（性价比最高）

**现状**：活跃周期内，每条消息都直接调用一次完整 LLM 判官（`compose_reply` 的 active 分支），
判断和生成用的是同一次调用、同一份人格 prompt——贵且慢。

**改进**：拆成两层：

```
第一层（便宜）：规则 + 极简 prompt（甚至小模型）
  - 消息是占位符/单字/纯表情？→ 直接跳过
  - 是群友间明确的一对一对话（@别人）？→ 降权
  - 含兴趣词（游戏名/梗词典命中）？→ 加权
第二层（贵）：通过第一层才让 DeepSeek 判官决定接不接
```

**参考数值**（来自社区生产配置）：基础插话概率 2%，回复后 120 秒内提升到 80%；
群消息频率超过阈值时概率对折；疲劳值随当日发言数线性衰减。

**改哪里**：`brain/app.py` 的 `decide_reply()` 前插入预筛函数。

## 2. 消息合并与拟人节奏

**现状**：群友连发三条"在吗""问个事""这个咋弄"，鱼对每条独立判断，
可能第一条就激动回复。回复也是一整段秒发。

**改进**：

- **合并**：同一发送者 N 秒（建议 4-8s）内的连续消息合并成一条再判断（茴香豆 pipeline 的标准做法）
- **分段发送**：鱼的长回复按句子拆成 2-3 条，间隔 1-3 秒发出
- **打字延迟**：回复长度越长，发出前等待越久（模拟打字）

**改哪里**：合并在 `brain/app.py` 的消息入口（需改为短暂缓冲而非立即判断）；
分段与延迟在 `hand/fish_hand.py` 的发送侧。

## 3. 记忆升级：滚动摘要 → 检索式记忆

**现状**：`summarize_group()` 每 30 条消息把聊天记录压成 150 字摘要，全文注入。
问题是摘要越滚越糊，三个月前的事等于不存在。

**改进**：

- 消息级入库（SQLite + 向量嵌入，如 bge-m3），回复前按当前话题**检索**相关历史
- 成员画像独立存储：每人一条持续更新的档案，而不是混在群摘要里
- 每日生成"昨日群报"，让鱼有"昨天"的概念

**参考**：dafeiyu-astrbot 的 livingmemory（bge-m3 嵌入 + session 作用域隔离）。

**改哪里**：`brain/app.py` 新增记忆模块替代 `summarize_group()`；
`system_prompt()` 从"注入摘要"改为"注入检索结果"。

## 4. 感知升级：让鱼真的"看见"

**现状**：图片/表情/语音全是占位文本，鱼只能猜。

**改进**（按依赖从小到大）：

- **链接解析**：消息含 URL 时抓标题摘要（纯 HTTP，无模型）
- **图片理解**：接一个视觉模型（如 qwen-vl / DeepSeek 多模态），占位符 → 一句图注再进上下文
- **语音转写**：ASR 后按文本处理（wxauto 的 `VoiceMessage.to_text()` 可调微信自带转文字）

**注意**：wxauto 免费版对图片消息的读取能力有限（多为 Plus 功能），
先确认你手上版本能拿到图片文件再动工。

**改哪里**：`hand/fish_hand.py` 的 `describe()`（占位符生成处）是真正的信息入口。

## 5. 人格迭代：用真实日志当教材

**现状**：人格 100% 靠 prompt，风格漂移靠运气。

**改进**：

- **few-shot 精选**：从 `/fish/logs` 里挑出群友反馈好的回复，固化进 persona 的口吻参考
- **差评分析**：把群友"她好像搞错了""好笨"附近的日志导出，归因是上下文问题还是人格问题
- **微调（大工程）**：攒几千条高质量对话后 LoRA 微调小模型，prompt 只留规则部分

**改哪里**：`brain/persona.txt`（快）；微调在仓库外进行（慢）。

## 6. 建立"智能"的度量

没有度量就没有改进。建议用日志计算三个指标，每次改动后对比：

| 指标 | 算法 | 目标 |
|---|---|---|
| 复读率 | 鱼的相邻发言的文本相似度（去重后） | 趋近 0 |
| 接话接受度 | 鱼主动发言后 60 秒内有群友接话的比例 | 越高越好 |
| 误判率 | 群友明确表达"别说了/搞错了"的次数 | 趋近 0 |

日志就在 `brain/data/logs/<群>/<日期>.jsonl`，每条都带 `mode` 字段，直接可分析。

## 代码地图（改动定位）

| 想改什么 | 在哪里 |
|---|---|
| 何时说话（全部决策） | `brain/app.py` → `decide_reply()` |
| 说什么（生成与判官 prompt） | `brain/app.py` → `compose_reply()` |
| 记忆沉淀与注入 | `brain/app.py` → `summarize_group()` / `system_prompt()` |
| 输出整形（橡皮擦） | `brain/app.py` → `outbound_eraser()` |
| 读懂消息（图片/引用/占位） | `hand/fish_hand.py` → `describe()` |
| 发送行为（分段/延迟/@） | `hand/fish_hand.py` → `main()` 的发送段 |
| 人格与梗 | `brain/persona.txt` / `brain/memes.txt` |

（复读率/接受度任意一项）。人格类改动请同时更新 `NOTICE`（如涉及新的改编来源）。
